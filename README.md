# Age.3 店舗チェック

銀座・原宿・浅草の店舗チェックリスト（全店共通版）のウェブアプリ。
出張中にスマホ縦持ち・片手で回れるように作ってある。元のエクセル
「Age3 店舗チェックリスト.xlsx」の 75項目・12カテゴリ・加重スコア・是正管理を
そのまま移植し、現地での入力と報告までを1つにまとめたもの。

UIは既存のAge.3アプリ（新商品チェックリスト）と同じトークン・同じ並びに揃えてある。

## できること

- **店舗チップで1タップ切替** — 銀座／原宿／浅草／まとめ。各チップに未入力バッジと「38/70 54%」を表示
- **店舗ごとの出し分け** — 共通66項目＋店舗別追加（銀座70／原宿70／浅草67項目）
- **12カテゴリ見出しごとの項目リスト** — 上に進捗バーと加重達成率
- **判定は4択の大ボタン** — ○＝1.0／△＝0.5／×＝0／対象外＝集計から除外。
  色だけでなく記号（✓ ／ ！ ／ ✕ ／ —）でも区別する
- **加重スコア** — Σ(重み×判定係数) ÷ Σ(重み)。S=5／A=3／B=1。
  80%以上＝緑／60〜79%＝黄／60%未満＝赤。**S項目に×が1件でもあれば総合何%でも赤**
- **警告バンド** — S項目の×、期限未記入の×、要改善件数をカード上部に出す
- **×をつけたら担当・期限が開く** — 未記入なら警告を出す
- **メモ＋写真添付** — 判定に関わらず**どの項目にも**写真を付けられる（複数枚まとめて選択可）。
  写真は端末内だけに保存し、長辺1280pxのJPEGに自動縮小する
- **要改善の絞り込み** — 「すべて／未入力／要改善」で×と△だけに絞り、その場で店長に見せる
- **前回との比較** — 各項目に前回の判定と「是正済み／改善／悪化」を表示
- **テキストをコピー／画像で保存・共有** — LINEにそのまま貼れる。画像はcanvasで生成するため
  オフラインでも作れる
- **PDF報告書** — 本編は**A4 最大2枚**（要約・カテゴリ別の表と達成度バー・前回比較・要改善一覧）。
  付けた写真は本編の後ろに写真ページとして続く。内容が少なければ1枚で終わる。
  ブラウザの「PDFとして保存」を使うので文字が選択でき、ファイルも軽い
- **連続×の可視化** — 同じ項目が2回以上続けて×なら「◯回連続×」を出す。
  毎回同じ×が並ぶ項目は現場の能力ではなく基準が無いことが原因なので、本部側の宿題として扱う
- **前回×の確認漏れ警告** — 前回×だったのに今回まだ未入力の項目を警告し、絞り込みで飛べる
- **期限アラート** — 期限切れ／3日以内／期限未記入を全店横断で集計し、どのタブにいても見える位置に出す
- **まとめタブ** — 3店の進捗バー比較、全店PDF報告書、是正管理台帳、視察履歴、JSONバックアップ
- **オフライン動作** — PWA。ホーム画面に追加すれば電波が弱くても開ける

## 使い方（現地）

1. 店舗チップを選ぶ（その場で今日の視察が作られる）
2. カテゴリ見出しごとに上から判定していく。×は担当・期限をその場で埋める
3. 「要改善」で絞り込み、×と△だけを店長に見せる
4. **テキストをコピー**または**画像で保存・共有**してLINEに送る
5. 記録として残すなら**PDF報告書を作る**（A4 最大2枚。下記）
6. 店を出る前に「まとめ」タブでJSONを書き出す（バックアップ）

## PDF報告書

「PDF報告書を作る」を押すと印刷ダイアログが開くので、出力先で **PDF** を選ぶ。

- iPhone … 送信先で「PDFとして保存」または共有シートからそのままLINEへ
- Mac … 左下の「PDF」→「PDFとして保存」
- Android / Windows … 送信先で「PDFに保存」

### 中身（どちらもA4 最大2枚。内容が少なければ1枚）

**店舗レポート**

1. 要約 — 総合スコア・判定・前回比を大きく出し、○/△/×/対象外、S項目の×、是正未完了、
   担当・期限が未記入の×、未入力をタイルで並べる
2. カテゴリ別 加重達成率 — 項目数・○△×・対象外・達成率・達成度バー・前回・前回比
3. 前回との比較 — 総合スコア／×件数／S項目の×／是正済み／悪化を、それぞれ「読み方」付きで。
   是正済みの項目名は下に一覧で出す
4. 要改善 — **写真主体のカード**（3列）。写真を大きく出し、その下に
   重要度・カテゴリ・項目・確認した事実・担当・期限・前回判定/悪化をテキストで置く。
   写真が無い項目は判定バーだけのカードになる
5. そのほかの写真 — カードに載らなかった項目（○・対象外、掲載枠から外れた要改善）の写真。
   1枚も落とさないための受け皿で、該当が無ければ出ない

**全店レポート**

1. 要約 — 3店平均、各店のスコア、S項目の×（全店）、是正未完了、うち期限切れ
2. 3店舗比較 — 視察日・視察者・スコア・達成度バー・S×・×・△・未入力・判定
3. カテゴリ別 3店比較 — 3店の達成率＋3店平均＋3本並べた達成度バー
4. 是正管理台帳（未完了）
5. 視察履歴

### 写真の載り方

要改善は表ではなく**カード**で出す。写真が主役で、詳細はその下にテキストで置く。
指摘と現物が1枚のカードに収まるので、店長に見せたときに「どこの何か」がすぐ伝わる。

- 1カードに写真は最大2枚（3枚目以降は「ほか◯枚」）。判定は写真の左上にバッジで出す
- 写真が無い項目も同じ並びに置く。空の写真枠は作らず、判定だけを大きく出す
- カードに載らなかった項目の写真は「そのほかの写真」に回す。
  **どの写真も落とさない**（○・対象外に付けた写真、掲載枠から外れた要改善の写真）
- **写真ぶんページが増える**ので、PDFボタンの下のチェックを外せば写真なしで出せる

### 印刷のタイミング（触るときは必ず読む）

報告書は印刷のときだけ DOM に載せる。ここのタイミングで2回踏んでいるので、
`lib/usePrint.ts` を変更するときは実機でPDFを出して確認する。

**出す前**：写真は端末内の IndexedDB から非同期に読む。読み終わる前に
`window.print()` を呼ぶと空枠のまま印刷される。次の順で待つ。

1. `usePhotoUrls` が報告書に載る写真をまとめて読み、揃ったら
   報告書のルートに `data-photos-ready="true"` を立てる
2. `usePrint` がその属性を最大15秒ポーリングして待つ
3. さらに全 `img` の読み込み完了と `document.fonts.ready` を待つ
4. `window.print()` を呼ぶ

**畳むとき**：`afterprint` で畳んではいけない。このイベントは「印刷ジョブを渡した時点」で
発火するため、利用者がまだプレビューを見ている最中に中身が消える
（iOS Safari のプレビューが真っ白／崩れる原因になる）。
`afterprint` は「畳んでよい状態になった」という印にとどめ、
実際に畳むのは**利用者がアプリに戻って操作したとき**（pointerdown / keydown）。
保険として5分後にも畳む。報告書は画面上では常に非表示なので、残っていても実害は無い。

### 掲載件数の上限

本編を2枚に収めるため、要改善は重要度順に**15件**、是正台帳は**16件**、視察履歴は**8件**まで。
写真は**36枚**（印刷が終わらなくなるのを防ぐための上限）。
溢れた分は「ほか◯件は本紙に載せていません」と件数を明記するので、
全件が載っていると誤読することはない。全件はアプリの画面かCSV書き出しで確認する。

上限を変えるときは `components/PrintReport.tsx` の `MAX_*` を触る。
要改善は1件増やすだけで本編が3枚目に落ちるので、変更したら必ずPDFを出してページ数を確認する。

### フォントについて

PDFは端末にインストール済みのゴシック体で描画される（フォントを埋め込まないので軽い）。
`app/globals.css` の `font-family` は Apple 系を先頭にしつつ、末尾に
`"Noto Sans CJK JP"` / `"Yu Gothic"` / `Meiryo` / `IPAPGothic` を並べてある。
これを省くと、日本語フォントの無い環境で中国語フォントに落ちて漢字が中国語字形になる。
明朝は意図的に一切入れていない。

## データの保存場所

**この端末のブラウザ内だけ**に保存される。サーバーには何も送らない。

- 視察データ … localStorage
- 写真 … IndexedDB

機種変更・ブラウザのキャッシュ削除で消えるため、JSONの書き出しが唯一の保険。
書き出したJSONは「まとめ → JSON読み込み（復元）」で戻せる。

## 開発

```bash
npm install
npm run dev     # http://localhost:3000
npm run build
```

Next.js 15（App Router）＋ React 19 ＋ Tailwind CSS v4。サーバー処理は無く、
全てブラウザ内で完結する。配色トークンは `app/globals.css` の `@theme` にまとめてあり、
既存のAge.3アプリと同じ値（`--brown:#3E2C23` ／ `--brown2:#5A4234` ／ `--line:#E7DED5`）を使っている。

### クラウド共有（Supabase）

既定は端末内保存だが、環境変数を入れると Supabase に切り替わる。
**未設定なら何も変わらない**ので、共有が必要になった時点で設定すればよい。
設定手順とSQLは [`docs/supabase.md`](docs/supabase.md) にある。

| 変数 | 用途 |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public キー |
| `NEXT_PUBLIC_SUPABASE_ROW_ID` | 省略可。既定 `age3-tenpo-checklist` |

動き方は「端末内が正、そのうえでクラウドへ写す」。電波が無い店舗でも入力は止まらず、
クラウドが落ちていてもアプリは動く。起動時はクラウドを優先して読み、失敗したら端末内で動く。

`@supabase/supabase-js` は静的 import していない。未設定の端末に配らないよう、
実際にクラウドへ行くときだけ動的に読み込む（別チャンクになる）。

**制約**：最後に保存した端末の内容で上書きされる。2人が同時に別々の店舗を入力すると
後勝ちになる。3店を1人で回る運用なら問題ないが、同時入力を始めるなら
店舗ごとに行を分けるか、項目単位の保存に作り変える必要がある。

### 保存先を別のものに差し替えるとき

UI からは localStorage / IndexedDB を一切触っていない。`lib/storage.ts` の
`Storage` インターフェース（`loadAll` / `saveAll` / `putPhoto` / `getPhoto` /
`deletePhoto` / `exportBundle` / `importBundle` / `clearAll` / `usageBytes`）を
実装した別モジュールを作り、`export const storage` の分岐に足せばよい。
Supabase 版（`lib/storage-supabase.ts`）がその実例で、端末内実装を引数で受け取って
上にかぶせる形にしてある（依存を一方向にして循環参照を避けるため）。

## デプロイ（Vercel）

1. [vercel.com/new](https://vercel.com/new) を開く
2. 「Import Git Repository」でこのリポジトリを選ぶ
3. Framework は Next.js が自動検出される。環境変数は不要
4. Deploy を押す

以降は `main` に push するたび自動でデプロイされる。
発行されたURLをスマホで開き、Safariの共有ボタン →「ホーム画面に追加」
（Androidはメニュー →「アプリをインストール」）で、アプリとして使える。
