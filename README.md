# Age.3 店舗チェック

銀座・原宿・浅草の店舗チェックリスト（全店共通版）のウェブアプリ。
出張中にスマホ縦持ち・片手で回れるように作ってある。元のエクセル
「Age3 店舗チェックリスト.xlsx」の 75項目・12カテゴリ・加重スコア・是正管理を移植し、
現地での入力と報告までを1つにまとめたもの。3店を1日で回れるよう、
実際に回すのは1店舗44項目に絞ってある（マスタの85項目は残してある）。

UIは既存のAge.3アプリ（新商品チェックリスト）と同じトークン・同じ並びに揃えてある。

## できること

- **店舗チップで1タップ切替** — 銀座／原宿／浅草／まとめ。各チップに未入力バッジと「26/44 60%」を表示
- **1店舗44項目** — 3店を1日で回れる量に絞ってある（マスタは85項目）。
  共通40項目＋店舗別追加。銀座44／原宿44／浅草44、12カテゴリすべてを網羅。
  うち**食中毒に直接効く項目が11件**（加熱・手洗い・体調申告・冷蔵温度・期限・
  いちごの洗浄・器具とスポンジの使い分けなど）
- **重要度の高い順に並ぶ** — 上から S（食品衛生・行政リスク）→ A（売上・品質・オペ）→ B（改善推奨）。
  上から順に埋めれば、危ないところから片付く。カテゴリは各項目に添えて表示する。
  見出しごとに入力数・×・△・達成率が出る
- **判定は4択の大ボタン** — ○＝1.0／△＝0.5／×＝0／対象外＝集計から除外。
  色だけでなく記号（✓ ／ ！ ／ ✕ ／ —）でも区別する
- **加重スコア** — Σ(重み×判定係数) ÷ Σ(重み)。S=5／A=3／B=1。
  80%以上＝緑／60〜79%＝黄／60%未満＝赤。**S項目に×が1件でもあれば総合何%でも赤**
- **警告バンド** — S項目の×、期限未記入の×、要改善件数をカード上部に出す
- **×をつけたら担当・期限が開く** — 未記入なら警告を出す
- **メモも写真も項目単位** — 各項目の判定ボタンの直下に、その項目専用の写真欄がある。
  どの項目の証拠写真かが1対1で分かる。タップ不要で見えている2列のグリッドで、
  縦横が混ざってもタイルが揃うよう 4/3 に固定して切り抜き、タップで元の比率のまま拡大する。
  **その場で撮る／アルバムから選ぶ**の両方に対応（どちらも複数枚まとめて可）。
  写真は端末内（IndexedDB）だけに保存し、長辺1600pxのJPEG（品質0.8）に自動縮小する
- **要改善の絞り込み** — 「すべて／未入力／要改善」で×と△だけに絞り、その場で店長に見せる
- **重要度で絞る** — 「Sだけ（銀座19／原宿23／浅草19項目）」「S＋A（41／44／43項目）」。
  3店を1日で回る日は、まずSだけを埋めて、時間が余ったらS＋A、じっくり見る日は全項目。
  項目は消さず表示を絞るだけなので、同じデータのまま後から続きを埋められる。
  スコアは常に全項目基準で、見ていない項目は未入力として分母から外れる（＝「見た範囲の点数」）
- **視察後まとめ** — 項目リストの下に自由記述が4つ（できていること／すぐ直すべきこと／
  仕組み・ルールを変えるべき点／人・配置・教育の課題）。書いた内容はPDF報告書の
  1ページ目に出る。○×の集計だけでは「で、何をするのか」が残らないため
- **過去の記録を開いて続きを入力** — 画面上部の「記録」から、その店舗の過去の視察を選ぶと
  そのまま呼び戻して追記・修正できる。「まとめ → 視察履歴」の「開く」からも飛べる。
  開いている記録はURL（`?store=浅草&id=…`）に持つので、再読み込みしても戻らない
- **前回との比較** — 各項目に前回の判定と「是正済み／改善／悪化」を表示
- **テキストをコピー／画像で保存・共有** — LINEにそのまま貼れる。画像はcanvasで生成するため
  オフラインでも作れる
- **PDF報告書** — 1ページ目に要約・カテゴリ別の表と達成度バー・視察後まとめ・前回比較を詰め、
  続けて要改善カードを2段組みで上から流し込む。**空白を作らず、文字も切らない**。
  写真はカードの中に出る。ブラウザの「PDFとして保存」を使うので文字が選択でき、ファイルも軽い
- **報告書を画面で見る** — 印刷に対応していないブラウザ（LINE等のアプリ内ブラウザ、
  ホーム画面に追加したアプリ）向けの逃げ道。同じ報告書を画面に出すので、
  スクリーンショットやiOSの「共有 → プリント」で残せる
- **連続×の可視化** — 同じ項目が2回以上続けて×なら「◯回連続×」を出す。
  毎回同じ×が並ぶ項目は現場の能力ではなく基準が無いことが原因なので、本部側の宿題として扱う
- **前回×の確認漏れ警告** — 前回×だったのに今回まだ未入力の項目を警告し、絞り込みで飛べる
- **期限アラート** — 期限切れ／3日以内／期限未記入を全店横断で集計し、どのタブにいても見える位置に出す
- **まとめタブ** — 3店の進捗バー比較、全店PDF報告書、是正管理台帳、視察履歴、JSONバックアップ
- **オフライン動作** — PWA。ホーム画面に追加すれば電波が弱くても開ける

## 使い方（現地）

1. 店舗チップを選ぶ（その場で今日の視察が作られる）
2. 3店を1日で回る日は、まず「重要度：Sだけ」で絞る。時間が余ったら「S＋A」→「すべて」に広げる
3. 上から順に判定していく（Sが先頭）。×は担当・期限をその場で埋める
4. 「要改善」で絞り込み、×と△だけを店長に見せる
5. **テキストをコピー**または**画像で保存・共有**してLINEに送る
6. 記録として残すなら**PDF報告書を作る**（下記）
7. 店を出る前に「まとめ」タブでJSONを書き出す（バックアップ）

書き忘れに後から気づいたら、画面上部の「記録」でその日の視察を選び直せば続きを入力できる。
別の店舗の記録なら「まとめ → 視察履歴 → 開く」から飛ぶのが早い。

## PDF報告書

「PDF報告書を作る」を押すと印刷ダイアログが開くので、出力先で **PDF** を選ぶ。

- iPhone … 送信先で「PDFとして保存」または共有シートからそのままLINEへ
- Mac … 左下の「PDF」→「PDFとして保存」
- Android / Windows … 送信先で「PDFに保存」

### 中身（A4。写真の枚数と要改善の件数でページが増える）

**店舗レポート**

1. 要約 — 総合スコア・判定・前回比を大きく出し、○/△/×/対象外、S項目の×、是正未完了、
   担当・期限が未記入の×、未入力をタイルで並べる
2. カテゴリ別 加重達成率 — 項目数・○△×・対象外・達成率・達成度バー・前回・前回比
3. 視察後まとめ — 視察者が書いた4つの所見。書いた欄だけ出る
4. 前回との比較 — 総合スコア／×件数／S項目の×／是正済み／悪化を、それぞれ「読み方」付きで。
   是正済みの項目名は下に一覧で出す
5. 要改善 — **写真主体のカード**。写真を出し、その下に重要度・カテゴリ・項目・
   確認した事実（メモ）・担当・期限・前回判定/悪化をテキストで置く。
   写真が無い項目は判定バーだけのカードになる。
   **2列に並べ、高さは中身なり**。項目名もメモも省略しない。事実（メモ）は太字で大きく出す。
   前の節の続きからそのまま始まるので、紙のあまりが出ない
   節番号は中身の有無で繰り上がる（写真が無い／前回が無いときはその節を飛ばす）

**全店レポート**

1. 要約 — 3店平均、各店のスコア、S項目の×（全店）、是正未完了、うち期限切れ
2. 3店舗比較 — 視察日・視察者・スコア・達成度バー・S×・×・△・未入力・判定
3. カテゴリ別 3店比較 — 3店の達成率＋3店平均＋3本並べた達成度バー
4. 是正管理台帳（未完了）
5. 視察履歴

### 入力画面の写真欄

項目名 → 判定ボタン → **その項目の写真欄** → メモ、の並び。写真欄は項目ごとに1つで、
開いた時点から見えている（タップして開く形にはしない）。

- 2列。`gap: 8px`、`aspect-ratio: 4 / 3`、角丸10px、枠線 `1px solid #E7DED5`
- 縦写真と横写真が混ざってもタイルの寸法が揃うよう、`object-fit: cover` で切り抜く。
  実測でタイルは 157×118px（iPhone縦 390×844 で計測）
- タップで拡大。拡大時は `object-fit: contain` で切り抜かず全体を見せる
- 空のときも1マス分の大きさでプレースホルダを置き、枠の大きさが分かるようにする
- 追加口は「＋ 撮影」と「＋ アルバムから選ぶ」の2つ。**`capture` を付けた input は
  iOSでカメラしか開かない**ので、アルバム用の input には付けない（付けないほうは
  iOSで「写真を撮る／フォトライブラリ/ファイルを選択」の選択メニューが出る）。
  空のプレースホルダはアルバム側につないである

写真は `Answer.photos`（項目 → 写真IDの配列）に持つ。実体は IndexedDB、
localStorage には写真IDしか入らない（base64を混ぜると数MBで容量が破綻するため）。
JSON書き出し（写真込み）は `Answer.photos` を全部たどって実体を同梱する。

### PDFでの写真の載り方

**写真だけを並べる節は置かない**。写真は要改善カードの中にだけ出す。
指摘と現物が1枚のカードに収まるので、店長に見せたときに「どこの何か」がすぐ伝わる。

- 2列のグリッドに並べる。改ページは行と行の間でしか起きないので、カードは割れない
- 1カードに写真は最大2枚（3枚目以降は「ほか◯枚」）。高さ28mm固定の `object-fit: cover`
  で、縦横が混ざっても並びは崩れない。判定は写真の左上にバッジで出す
- 写真が無い項目も同じ並びに置く。空の写真枠は作らず、判定だけを大きく出す
- 写真を載せたくないときは、PDFボタンの下のチェックを外す

### 印刷のタイミング（触るときは必ず読む）

報告書は**常に** DOM に載せてある（画面には出ない）。ここのタイミングで3回踏んでいるので、
`lib/usePrint.ts` を変更するときは実機でPDFを出して確認する。

**出す前**：写真は端末内の IndexedDB から非同期に読む。読み終わる前に
`window.print()` を呼ぶと空枠のまま印刷される。

1. `usePhotoUrls` が報告書に載る写真をまとめて読み、揃ったら
   報告書のルートに `data-photos-ready="true"` を立てる
2. ボタンを押した時点で揃っていれば、**その場で同期的に** `window.print()`
   （iOSはユーザー操作から離れると印刷を無視するため。詳細は下の項）
3. 揃っていなければ `usePrint` が最大15秒ポーリングし、
   `document.fonts.ready` も待ってから呼ぶ

**畳むとき**：`afterprint` で畳んではいけない。このイベントは「印刷ジョブを渡した時点」で
発火するため、利用者がまだプレビューを見ている最中に中身が消える
（iOS Safari のプレビューが真っ白／崩れる原因になる）。
`afterprint` は「畳んでよい状態になった」という印にとどめ、
実際に畳むのは**利用者がアプリに戻って操作したとき**（pointerdown / keydown）。
保険として5分後にも畳む。報告書は画面上では常に非表示なので、残っていても実害は無い。

### 改ページ（触るときは必ず読む）

**節の途中で改ページしない**。見出し・表・注記をまとめて `.pr-keep`
（`break-inside: avoid`）で囲ってあり、入り切らないときは節ごと次のページへ送る。
是正台帳のように1ページに収まらない表だけは自動で割れるが、そのときは見出し行を繰り返す。

**枠から文字がはみ出さない／大きな空白を作らない**。要改善カードの高さは**固定しない**。

- 高さを固定すると、短いカードの中に大きな空白ができ、長いカードでは文字が切れる。
  どちらも過去に踏んでいる。`height` も `-webkit-line-clamp` も使わず、中身なりにする
- 並べ方は**グリッド**（2列・`align-items: start`）。段組み（`columns`）は詰まるが、
  ブラウザによっては改ページでカードが割れる。グリッドなら改ページは行と行の間でしか
  起きないので、カードは絶対に割れない（1ページに10〜12枚）
- 要改善は前の節の続きから始める。ページの頭から始めると、前のページの下が大きく余る
- 担当・期限とタグ（前回／悪化／連続×）は1行にまとめる
- 変更したら、印刷CSSを当てた状態で `scrollHeight > clientHeight` の要素が
  0件であることを必ず確認する（`.pr-card-body` / `.pr-card` / `.pr-card-title` / 表のセル）

### 出力ファイルの名前

どの店舗の、いつの記録かがファイル名で分かるようにしてある。

| 出力 | 名前 |
| --- | --- |
| PDF（店舗） | `Age3_店舗チェック報告書_浅草_2026-09-11` |
| PDF（全店） | `Age3_全店報告書_2026-09-11` |
| 画像で保存・共有 | `Age3_浅草_2026-09-11.png` |
| 是正台帳CSV／履歴CSV／JSON | `Age3_是正管理_2026-09-11.csv` など（全店まとめなので店舗名は付けない） |

PDFの名前は `document.title` から取られる。`lib/usePrint.ts` が印刷のあいだだけ
タイトルを差し替え、利用者がアプリに戻って操作したときに元へ戻す
（プレビューを見ている最中に戻すと、保存名が元のタイトルになってしまう）。

### 掲載件数の上限

要改善は重要度順に**20件**、是正台帳は**16件**、視察履歴は**8件**まで。
溢れた分は「ほか◯件は本紙に載せていません」と件数を明記するので、
全件が載っていると誤読することはない。全件はアプリの画面かCSV書き出しで確認する。

上限を変えるときは `components/PrintReport.tsx` の `MAX_*` を触る。
増やすと最後のページが余りやすいので、PDFを出して最終ページの埋まり具合を見る。

### 44項目の選び方（入れ替えたいとき）

`lib/checklist.ts` の `CORE_IDS` に、店舗ごとの項目IDを並べてある。
ここを書き換えるだけで入れ替わる。`CHECKLIST`（マスタ）は消していないので、
外した項目もIDを足せばいつでも戻せる。

- 共通40項目 … 共通のS項目19件（食品衛生・食品安全・行政/近隣リスク）を全部入れ、
  残り21枠を「S項目が無いカテゴリ」と「現場で一目で判定できるA項目」に配分した
- 銀座・原宿 … 共通40＋店舗別追加4 ＝ 44
- 浅草 … 店舗別追加が1件しかないため、観光地特有の3項目
  （入店時の声かけ／提供時間／ゴミ箱まわり）を足して44に揃えている

うち id 77・78・80 は元エクセルに無かった項目で、こちらで足したもの。
生クリーム＋カットいちご＋揚げという商品構成では、加熱工程で止められない
食中毒経路（生果物の洗浄・器具の交差汚染・洗い物の使い回し）が残るため。
現場で見た瞬間に○×が付けられる形だけを残してある
（「作業中も10℃以下」「持ち帰り時間の案内」はオペレーション上まわらないため入れていない）。

id 81〜87 も現場から足したもの。81 ショーケースの見え方、82 単価アップの声かけ、
83 店に入った瞬間の空気感、84 スタッフの表情・姿勢・声量、85 商品名の正確さ、
86 冷蔵・冷凍庫内の整理、87 スタッフ同士の声掛け・連携。
82 は「やっているか」ではなく「100%できているか」で判定する。
売っている物・特典が変われば 82 の文言も直すこと。

入れ替えたら、12カテゴリが全部残っているか・共通のS項目を落としていないかを必ず確認する。

### iPhoneでPDFが出ないとき（触るときは必ず読む）

iOS Safari は `window.print()` を**利用者が押した操作の中で呼ばないと黙って無視する**。
写真の読み込みを待ってから呼ぶと、待ち時間の分だけ操作から離れてしまい、
ボタンを押しても何も起きない。そこで

- 報告書は**常に**（画面には出さずに）DOMへ置いておき、写真を先に読み終わらせる
- ボタンを押した時点で写真が揃っていれば、**その場で同期的に** `window.print()` を呼ぶ
  （実測：クリックから1ms）
- 揃っていないときだけ、従来どおり待ってから呼ぶ（ボタンは「写真を読み込み中…」になる）

さらに、LINEやInstagramのアプリ内ブラウザ・ホーム画面に追加したPWAは
**印刷自体に対応していない**。`beforeprint` / `afterprint` が来なければ
「出なかった」とみなして案内を出し、「報告書を画面で見る」（`.print-preview`）へ逃がす。
プレビューはA4の組版のまま `zoom` で画面幅に縮めて出すので、
スクリーンショットやiOSの「共有 → プリント」でそのまま残せる。

### アプリアイコン

`assets/icon.svg` が原本。ラスタ画像は次で書き出す（Chromiumで描画するだけなので
画像ライブラリは足していない。playwright が無ければ `npm i -D playwright`）。

```bash
node scripts/make-icons.mjs
```

| ファイル | 用途 |
| --- | --- |
| `public/icon-192.png` / `icon-512.png` | PWA（ホーム画面に追加） |
| `public/icon-maskable-512.png` | Android。外周を丸く切られる前提で内側78%に収めた版 |
| `public/apple-touch-icon.png` | iOSのホーム画面（180px） |
| `public/favicon.png` | ブラウザのタブ（64px） |

差し替えたら `public/sw.js` の `CACHE` の版番号を上げること。
上げないと、すでに追加した端末に古いアイコンが残る。

### フォントについて

PDFは端末にインストール済みのゴシック体で描画される（フォントを埋め込まないので軽い）。
`app/globals.css` の `font-family` は Apple 系を先頭にしつつ、末尾に
`"Noto Sans CJK JP"` / `"Yu Gothic"` / `Meiryo` / `IPAPGothic` を並べてある。
これを省くと、日本語フォントの無い環境で中国語フォントに落ちて漢字が中国語字形になる。
明朝は意図的に一切入れていない。

## データの保存場所

**この端末のブラウザ内だけ**に保存される。サーバーには何も送らない。

- 視察データ … localStorage
- 写真 … IndexedDB

機種変更・ブラウザのキャッシュ削除で消えるため、JSONの書き出しが唯一の保険。
書き出したJSONは「まとめ → JSON読み込み（復元）」で戻せる。

### クラウド共有（Supabase）

既定は端末内保存だが、環境変数を入れると Supabase に切り替わる。
**未設定なら何も変わらない**ので、共有が必要になった時点で設定すればよい。
設定手順とSQLは [`docs/supabase.md`](docs/supabase.md) にある。

| 変数 | 用途 |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public キー |
| `NEXT_PUBLIC_SUPABASE_ROW_ID` | 省略可。既定 `age3-tenpo-checklist` |

動き方は「端末内が正、そのうえでクラウドへ写す」。電波が無い店舗でも入力は止まらず、
クラウドが落ちていてもアプリは動く。起動時はクラウドを優先して読み、失敗したら端末内で動く。

`@supabase/supabase-js` は静的 import していない。未設定の端末に配らないよう、
実際にクラウドへ行くときだけ動的に読み込む（別チャンクになる）。

**制約**：最後に保存した端末の内容で上書きされる。2人が同時に別々の店舗を入力すると
後勝ちになる。3店を1人で回る運用なら問題ないが、同時入力を始めるなら
店舗ごとに行を分けるか、項目単位の保存に作り変える必要がある。

### 保存先を別のものに差し替えるとき

UI からは localStorage / IndexedDB を一切触っていない。`lib/storage.ts` の
`Storage` インターフェース（`loadAll` / `saveAll` / `putPhoto` / `getPhoto` /
`deletePhoto` / `exportBundle` / `importBundle` / `clearAll` / `usageBytes`）を
実装した別モジュールを作り、`export const storage` の分岐に足せばよい。
Supabase 版（`lib/storage-supabase.ts`）がその実例で、端末内実装を引数で受け取って
上にかぶせる形にしてある（依存を一方向にして循環参照を避けるため）。

## デプロイ（Vercel）

1. [vercel.com/new](https://vercel.com/new) を開く
2. 「Import Git Repository」でこのリポジトリを選ぶ
3. Framework は Next.js が自動検出される。環境変数は不要
4. Deploy を押す

以降は `main` に push するたび自動でデプロイされる。
発行されたURLをスマホで開き、Safariの共有ボタン →「ホーム画面に追加」
（Androidはメニュー →「アプリをインストール」）で、アプリとして使える。
