# Age.3 嘉麻店 日報アプリ

株式会社ANCHOR／Age.3 嘉麻店の日報を、スマホだけで入力してLINEに送るためのウェブアプリ。

これまで嘉麻店の日報は2つに分かれていた。
冷凍在庫（缶）とスイーツサンド在庫は紙に手書きして写真を撮りLINEへ、
売上や販売数はiPhoneで文章を打ってLINEへ。書き方が人によって変わり、
あとから並べて比べることができなかった。

このアプリは、その2つを1つの入力画面にまとめる。手書きと写真は使わない。
入力はすべて、文字を打つか、プルダウン・トグル・チェックボックス・
数値ステッパーを押すかのどちらかで終わる。

一番の目的は、**社員が居ない日にアルバイトだけでどこまで店が回っているか**を、
経営側が数字で見られるようにすること。だから日報には必ず社員の在店有無を
記録させ、履歴画面ではその日を色分けし、分析画面では社員ありの日と
並べて比べられるようにしてある。

## 画面

| 画面 | パス | 何をするところか |
| --- | --- | --- |
| 日報 | `/` | 売上・販売数・シフトなど。在庫数は扱わない |
| 在庫チェック | `/stock` | スイーツサンド在庫と冷凍在庫（缶）を数え、その場で報告する |
| 日報カード | `/preview` | 1枚のカードにまとめて表示し、LINEに送る／画像で保存する |
| 履歴 | `/history` | 過去の日報を新しい順に並べる。社員なしの日を色分けする |
| 分析 | `/dashboard` | 社員あり／なしの比較表と、作成数・客数・売上の推移グラフ |
| 設定 | `/settings` | スタッフ名・在庫の目標数・商品名を書き換える（管理PINが要る） |

## 入力する項目

1. **基本情報** — 日付（当日が自動で入る・変更可）と曜日（自動表示）
2. **シフト・人員体制** — 出勤人数、製造担当者、販売担当者、社員の在店有無、
   アルバイトのみの時間帯とその対応状況
3. **缶商品の当日製造数** — その日に何個作ったか。在庫数は入れない
5. **売上情報** — 総売上／現金／CR／PayPay／QR／アンカーチケット／客数／
   客単価（自動計算）／Uber件数・売上／口コミ件数／総口コミ数
6. **お客様情報** — 客層、来店ピーク時間帯、リピーター数、新規客数
7. **商品別販売数** — アサイーボウル・かき氷・季節揚げサンド・アイス揚げサンド・
   ボタ山ソフト・ドバイ餅。一番売れた商品は自動で判定して光らせる
8. **手が空いた時に行った作業** — チェックボックスと自由記述
9. **口コミ返信件数** — 銀座／浅草／原宿／嘉麻、合計は自動
10. **その他連絡事項** — 自由記述

商品名と目標数の初期値は、店舗に貼ってある紙2枚（「冷凍ストック」「在庫表」）から
そのまま写している（`lib/masters.ts`）。目標数は設定画面で変えられる。

## 充足率の見かた

現在庫 ÷ 目標数で出す。

- 🟢 **十分** — 80%以上
- 🟡 **やや不足** — 50%以上80%未満
- 🔴 **大幅不足** — 50%未満

まとめの充足率は、**在庫を入力し終えた品目だけ**で計算する。
まだ数えていない品目の目標まで分母に入れると、
数え終わる前はいつも「大幅不足」に見えてしまうため。

## LINEへの送り方

日報カードの画面に3つのボタンがある。

- **LINEに送る（テキスト）** — Web Share API（`navigator.share`）で端末の共有シートを
  開き、LINEを選んで送る。LINE公式アカウントのAPIキーなどは要らない。
  共有シートが使えない端末では、文面をクリップボードにコピーして知らせる
- **日報カードを画像で保存／共有** — カードをPNGにする。画像を共有シートに
  渡せる端末はそのまま共有、渡せない端末は端末に保存してLINEに手で添付する
- **在庫の内訳だけ送る** — 品目ごとの在庫と作成数を並べた長い文面を送る

PNGは HTML を画像に変換するのではなく、`lib/cardImage.ts` が canvas に直接
描いている。HTML変換はiPhoneのSafariで白紙になったり書体が入れ替わったりして
現場で当てにできないため。文字はすべてゴシック体。

## 在庫チェックと日報は別の業務

紙の時代と同じで、在庫を数えるのと日報を書くのは別の仕事なので、画面ごと分けてある。

| | 在庫チェック `/stock` | 日報 `/` |
| --- | --- | --- |
| 扱うもの | スイーツサンド在庫（27マス）／冷凍在庫（缶）の現在庫数（30品目） | 売上・お客様・販売数・シフト・缶商品の当日製造数 |
| 報告 | その画面から直接。文面／表の画像2種 | 日報カードから |
| 提出済みの印 | `stockSentAt` | `sentAt` |

日報で在庫数を入れ直す必要はない。逆に、缶商品を何個作ったかは日報側で入れる。
数えること（在庫チェック）と、作った数の報告（日報）を分けるため。

保存は日付ごとに1件のまま。片方を送っても、もう片方の入力は消えない。
空にするのは自分の担当範囲だけで、実装は `clearStockFields` / `clearReportFields`。

在庫チェックは報告済みでも、報告した中身をそのまま送り直せる。
「文面を送ったあとに画像も送る」を、入力し直さずにできるようにするため。

## 送信すると入力が空になる

「LINEに送る（テキスト）」で日報を送れると、その日報に送信の印（`sentAt`）が付く。
印の付いた日を入力画面で開くと、**入力欄は空の状態で開く**。次の日報をすぐ
書き始められるようにするため。

送った中身は消えない。履歴と分析にはそのまま残る。

空で開いたあと何も打たなければ保存もしない（自動保存は何か入力した時点から動く）ので、
送信済みの日報が空で上書きされることはない。打ち間違いを直したいときは、
画面上部の「送信した内容を呼び戻して直す」で中身を戻せる。

在庫の内訳テキストや画像の保存は送信扱いにしない。日報そのものを送ったときだけ。

## 保存先

入力は打つそばから自動保存される。保存先は2つ。

- **端末内（localStorage）** — 必ず書く。電波が切れても入力が消えない
- **データベース** — `POSTGRES_URL` が設定されているときだけ。
  ここに入ったぶんは全員が同じ履歴を見られる

データベースを繋がなくてもアプリは動く。その場合、履歴と分析はその端末で
入力したぶんだけになる。今どちらで保存されているかは設定画面に出る。

テーブルは初回アクセス時に `CREATE TABLE IF NOT EXISTS` で自動的に作られる
（`reports` と `app_settings` の2つ）。

## アクセス制限

PINは2段階ある。合っていればハッシュをCookieに入れ、`middleware.ts` が
それを見て通す。PIN自体はCookieに入れない。

| | 環境変数 | 初期値 | 守る範囲 | 有効期間 |
| --- | --- | --- | --- | --- |
| 入店PIN | `APP_PASSCODE` | `1959` | アプリ全体 | 90日 |
| 管理PIN | `ADMIN_PASSCODE` | `3030` | 設定画面と設定の書き込み | 1日 |

入店PINはアルバイトを含む全員が使う。管理PINは設定画面（`/settings`）だけに
かかっていて、スタッフ名・在庫の目標数・商品名を書き換えられる場所を守る。
入店PINを知っていても設定は開けない。

`POST /api/settings` にも管理PINがいる。`GET` は全画面が目標数を読むので開けてある。

Cookieのハッシュには段階名を混ぜてあるので、入店側のCookieを管理側に
使い回すことはできない。

**本番では両方とも環境変数で設定すること。** 初期値はこのリポジトリに
書いてあるので、そのままだと誰でも分かる。

## 開発

```bash
npm install
npm run dev     # http://localhost:3000
npm run build
npm run start
```

## Vercelへのデプロイ

このアプリはリポジトリ直下ではなく `age3-kama-report/` の中にある。
Vercelでプロジェクトを作るときは **Root Directory に `age3-kama-report` を指定する**。

1. Vercel で New Project → このリポジトリを Import
2. **Root Directory** に `age3-kama-report` を入れる
3. Environment Variables に以下を入れる

   | 変数名 | 内容 |
   | --- | --- |
   | `APP_PASSCODE` | 入店PIN。店舗の全員で共有する |
   | `ADMIN_PASSCODE` | 管理PIN。設定画面に入れる人だけに教える |
   | `POSTGRES_URL` | 日報を残すデータベースの接続文字列。後から足してもよい |

4. Deploy

データベースは Vercel の Storage から Neon（旧 Vercel Postgres）を足すと
`POSTGRES_URL` が自動で入る。繋いだ次のアクセスでテーブルが作られる。

## 作りの中身

- Next.js 15（App Router）／TypeScript／Tailwind CSS v4
- グラフ用のライブラリは入れていない。見せたいのは日ごとの高さの差だけなので
  SVGを直接描いている（`components/Charts.tsx`）
- 画面幅は560pxで止め、下タブは親指の届く位置に固定。押す場所は48px以上

```
app/          画面とAPI
components/   画面の部品
lib/
  masters.ts  商品マスタ（紙2枚から写した初期値）
  types.ts    日報1件のかたち
  calc.ts     充足率・客単価・最多販売商品などの計算
  format.ts   LINEに貼るテキスト
  cardImage.ts 日報カードのPNG
  storage.ts  端末内とサーバーの保存
  db.ts       Postgres
  auth.ts     共通パスコード
```
